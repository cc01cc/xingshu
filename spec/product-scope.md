## 1. 文档目的

本 SPEC 定义星枢（XS）面向用户和 Agent 提供的产品能力、使用边界与验收场景。它说明 XS 要解决什么问题，不规定索引引擎、存储物理路径、HTTP 路由或 CLI 参数。

## 2. 产品定位

XS 是本地项目与资源索引及管理中枢。人类用户与 Agent 通过 XS 发现、检索和读取操作者注册的仓库根目录中的仓库，并按仓库及操作策略执行受控 Git 操作。

XS 不是 Git forge，也不替代 Git 的版本控制语义。Git 仓库是当前首要支持的资源类型。

所有产品数据来源均由操作者通过 XS 注册为仓库根目录。XS 只扫描已注册根目录，不预置仓库集合或隐式发现其他目录。

## 3. 参与者与入口

产品能力不按 actor 类型划分：人类用户与 Agent 可执行相同的产品操作，界面/协议的区别仅用于适配交互方式和结果呈现。

双方共享的产品能力集合（括注为交付阶段，详见 §5）：注册/管理 roots、触发扫描、浏览/筛选仓库、搜索代码/路径、读取内容、管理标签/策略（已实现）；执行 clone（首期补足）、pull/move（已实现）、归档（后续增强）；管理备份（已实现）。

| 参与者 | 目标入口类别 | 结果呈现 |
|---|---|---|
| 人类用户 | WebUI、CLI | 可视化显示环境、仓库目标、策略来源、操作状态和结果 |
| Agent / 自动化 | CLI、HTTP API | 可解析返回目标、策略来源、状态、结果和错误 |

- 入口只改变交互形式与结果呈现；root 管理/扫描不得只留给人类，代码搜索/内容读取也不得只开放给 Agent。
- 仓库策略、环境隔离和破坏性操作确认按操作与目标生效，不按 actor 身份删减功能。
- MCP 不是本 SPEC 的前置要求。

## 4. 仓库根目录与环境模型

产品流程为：

```text
操作者注册仓库根目录
  -> XS 扫描并建立仓库/内容索引
  -> 用户或 Agent 搜索、读取仓库
  -> 明确选择仓库和操作策略
  -> 在所选环境的存储根中执行获准的 Git 操作
```

- 操作者显式注册仓库根目录；XS 只扫描已注册根目录，不隐式发现其他目录。
- 仓库的扫描、搜索、读取和写操作均以已注册根目录、所选仓库及其生效策略为边界。只读根或禁止某操作的仓库不得被该写操作修改。
- `clone` 在操作者明确选择的目标根目录创建仓库；`pull/update` 只作用于操作者明确选择且策略允许更新的已注册仓库，不按同名仓库隐式切换目标。
- 测试与生产使用相互独立的存储根。隔离范围至少覆盖仓库目录、元数据数据库、全文检索索引和临时/缓存产物；每种产物的环境归属必须可识别。
- 测试操作不得写入生产存储，生产操作不得写入测试存储；XS 无法确认目标环境或根目录时必须拒绝写操作，而不是猜测或回退到共享目录。
- 根目录的物理路径、索引如何映射到不同部署环境以及 Git remote 的具体解析方式由后续技术设计确定，本 SPEC 不规定实现方式。

## 5. 能力范围与优先级提案

以下能力阶段划分和优先级已随本 SPEC 于 2026-09-29 经用户确认冻结。“后续增强”是认可的远期范围，不是首期交付要求。XS 已有能力是产品基线的一部分，应在后续演进中保留；首期补足统一检索、读取和仓库获取（clone/pull）闭环。

### 5.1. 现有实现基线（应保留）

- **仓库根目录与扫描**：注册、列出和移除仓库根目录；扫描并维护仓库目录索引。
- **标签与策略**：为仓库添加/移除星枢领域标签（不是 Git tag）；按标签筛选仓库，并支持仓库级策略覆盖标签级策略。多个标签均有策略时，必须按稳定、可解释的规则选出一个生效策略；具体优先序由策略契约规定。
- **仓库状态与操作**：查看仓库状态、有效策略和冲突；对已注册仓库执行策略化 pull/update 与跨根搬迁。
- **备份管理**：创建、列出、恢复和按保留策略清理仓库备份。恢复前保留当前状态作为可恢复副本；清理默认预览将影响的备份，执行前明确显示目标及影响并要求显式确认。
- **任务与统计**：查看扫描、pull 等任务结果、失败原因及仓库/标签等维度统计。

### 5.2. 首期补足提案

- **仓库目录检索增强**：在现有名称、owner、路径、标签、root 和 status 过滤基础上，清楚展示索引结果、仓库来源信息与操作环境。
- **跨仓代码与路径搜索**：补足当前尚无的跨仓代码全文与文件路径搜索；结果能定位到仓库、版本、路径和匹配位置。
- **内容读取增强**：在现有变更 diff 能力之外，从搜索结果读取指定仓库版本和路径的文本内容及必要上下文。
- **仓库 Clone**：补足当前仓库入口未提供的 clone 能力，将用户选择的仓库 clone 到明确选择的目标根目录。
- **安全状态可见**：查询结果和写操作反馈能区分仓库根目录、仓库操作策略、测试/生产环境，以及索引/更新任务状态。

### 5.3. 后续增强提案

- **仓库逻辑归档与恢复**：提供可逆的归档/恢复能力。归档仓库默认不出现在活动仓库视图和批量操作中，但仓库文件及备份不被物理删除；用户可在归档视图中查找并恢复。此能力不同于创建备份或生成归档文件；具体用状态、标签还是策略表达，留给后续技术设计。
- 选择分支、tag 或 commit 作为读取/导出目标。
- 按目录导出、工作树检出或创建隔离的临时工作副本。
- 更细的语言、文件类型、大小、更新时间和仓库状态过滤。
- 任务取消、重试、批量更新计划及详细进度。
- 对 Agent 暴露更专用的协议入口；是否采用 MCP 另行评估。

### 5.4. 待评估

- Zoekt 等跨仓全文检索后端的适用性、平台支持、资源开销和代表性数据性能。此项是技术评估，不承诺采用 Zoekt。
- 符号搜索、定义/引用检索及其他代码智能能力。

## 6. 安全与失败边界

- 不允许的仓库操作必须在任何修改前拒绝；错误响应应标明目标仓库及拒绝策略。
- 测试/生产环境及目标根目录必须在写操作前明确；目标属于另一环境或无法判定时，操作应在修改前失败并说明原因。
- Clone 或更新失败时，XS 必须显示目标仓库和结果状态；不应把未完成的仓库伪装为可用，也不应自动改写其他仓库或环境来恢复。
- 备份恢复和备份清理等可能覆盖或删除数据的操作必须显示目标与影响，并要求显式确认。
- 归档/恢复不得丢弃仓库文件或备份；归档项不得进入默认批量写操作。
- 普通搜索和读取不应隐式触发 pull、clone、checkout 或其他改变仓库状态的动作。
- 日志与结果不得泄露仓库 remote 中的凭证或访问 token。

## 7. 验收场景

| 编号 | 场景 | 前置状态 | 操作 | 预期结果 |
|---|---|---|---|---|
| P1 | 查找并读取已注册仓库 | 仓库根目录已注册并完成索引 | 人类用户或 Agent 搜索代码并打开命中位置 | 结果能定位到仓库和文件位置；读取成功；搜索/读取不改变仓库状态 |
| P2 | Clone 到测试根 | 用户选择了仓库与测试目标根 | 请求 clone | 新仓库只写入测试根；生产存储和其他根不变 |
| P3 | 更新测试仓库 | 测试根中的仓库已注册且策略允许更新 | 对该仓库请求 pull/update | 仅更新所选测试仓库；结果和失败原因可见；生产存储不变 |
| P4 | 更新生产仓库 | 生产根中的仓库已注册且策略允许更新 | 对该仓库请求 pull/update | 仅更新所选生产仓库；不得把测试根中的同名仓库作为目标 |
| P5 | 标签管理与检索 | 仓库已注册 | 添加星枢标签并按标签搜索 | 仓库出现在对应标签结果中；仓库策略优先于标签策略，多标签策略按确定顺序取生效项 |
| P6 | 备份与恢复 | 仓库已注册且备份可用 | 创建备份并请求恢复 | XS 显示备份与恢复目标；恢复前保留可恢复的原状态；恢复失败时报告失败并指出恢复副本；其他根和环境不变 |
| P7 | 备份清理 | 仓库有多个备份 | 预览后请求清理 | 预览列出将清理的备份；未显式确认前不删除 |
| P8 | 归档与恢复仓库 | 仓库已注册 | 归档后再从归档视图恢复 | 归档项退出默认活动视图和批量操作但仓库/备份数据保留；恢复后重新进入活动视图；不把归档误当成创建备份 |
| P9 | 策略拒绝写入 | 所选仓库的生效策略禁止当前操作 | 对禁止更新的仓库请求 pull/update，或请求被策略拒绝的 move/备份操作 | 操作在任何写入前被拒绝，并指出仓库与拒绝原因 |
| P10 | 跨环境误操作 | 操作上下文与目标根环境不一致 | 在测试上下文请求更新生产根中的仓库，或反向操作 | 操作被拒绝；两个环境的数据保持不变 |

## 8. 非目标与待后续决策

- 本产品不托管远程 Git 服务、不替代 Git，也不在本阶段详细定义非 Git 资源类型。
- 本产品不绑定任何机器相关路径或预置参考仓库集合；根目录由操作者配置。
- 本 SPEC 不选择 Zoekt 或其他检索引擎，不规定索引部署方式、数据库 schema、物理目录结构或资源阈值。
- 多标签策略的具体优先顺序、备份存储形式/目标/保留阈值由后续策略与备份技术契约确定；本 SPEC 仅要求有效结果可解释、数据操作安全。
- 本 SPEC 不规定具体 HTTP 路由、CLI 参数、MCP schema 或 UI 视觉样式；这些应在对应设计或实现计划中确定。
- 本 SPEC 的产品范围、能力优先级和验收场景已冻结为后续实现 PLAN 的需求基线；具体实现仍需后续实现 PLAN 授权。
