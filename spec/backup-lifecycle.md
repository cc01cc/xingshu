## 1. 目的与术语

定义操作者显式发起的仓库备份、列表、恢复、保留与清理能力。本文把三种行为严格区分（术语见 `README.md`）：

- **独立仓库备份**：操作者主动创建、可列举、可恢复的副本。
- **pull 冲突备份**：由仓库生命周期操作触发，用于保护冲突仓库并继续更新；它的原子性和失败策略由 lifecycle SPEC 定义。
- **逻辑归档**：不创建备份文件，不删除仓库文件；由 lifecycle SPEC 定义。

本 SPEC 不选择备份格式或存储后端，只定义用户可观察能力和数据保护边界。

## 2. 参与者与结果

| 参与者 | 能力 | 入口类别 | 约束 |
|---|---|---|---|
| 人类用户 | 创建/列举/恢复备份，预览并执行清理 | WebUI、CLI | 显示目标、影响和恢复副本；破坏性操作需确认 |
| Agent / 自动化 | 创建/列举/恢复备份，预览并执行清理 | CLI、HTTP API | 可解析取得同一能力的目标、恢复副本和逐项结果；需确认时返回待确认，不能自我确认 |
| 仓库生命周期操作 | 请求 pull 冲突保护 | Core 服务 | 只调用独立备份能力，不重复定义快照格式、列表或恢复规则 |

人类用户与 Agent 的备份功能集合相同；入口只改变交互和结果呈现。任务结果使用 `README.md` 统一状态枚举（success/skipped/pending_confirmation/failed）；应能查出每次操作的源仓库、备份项和目标环境。本地人类操作者是确认主体；Agent 可请求并等待确认但不能自我确认，不引入多用户审批层级。

pull 冲突备份不进入用户备份列表、不计入保留数量，除非用户明确批准合并两者；逻辑归档同样不计为备份。

## 4. 备份对象与目标

- 操作者对一个明确注册的仓库创建备份；结果关联源仓库、目标环境、创建时间、可用性和可选 tar/压缩包形式。
- 备份目标必须在当前 XS 环境内且可识别；测试与生产备份根分离，测试任务不能读取、覆盖或清理生产备份。
- 操作者可以列出某一仓库的备份并辨别目录快照/tar 文件等可用形式；具体格式、路径和压缩算法留给技术设计。

### 4.1. 创建与列表

- 创建备份前确认源仓库存在、可读且属于已注册 root；目标环境和保存位置清楚。
- 备份应可被仓库身份、创建时间和形式识别；创建失败时不得登记为可恢复成功项。
- 操作者/Agent 可列出指定仓库的备份，结果包含足以选择恢复项的标识和可用状态。

### 4.2. 恢复

- 恢复是对明确仓库目标的破坏性操作；恢复前要展示源备份、目标仓库和影响，并要求明确确认。
- 恢复前保留目标仓库当前状态为 pre-restore recovery copy；恢复失败需报告失败阶段并指出可用恢复副本，不得静默丢弃原仓库状态。
- 若目标仓库不存在、备份损坏/不兼容、环境不匹配或恢复副本不可创建，则在有数据覆盖前拒绝或明确进入失败/人工处置状态。
- 成功恢复后，仓库仍归属于原明确 root/环境；不得顺带修改同名仓库或另一环境。

### 4.3. 保留与清理

- 操作者可按仓库配置最大保留数量；备份创建完成后可按规则提出清理旧项。
- 清理先给出纯预览，列出将删除的确切备份项；实际删除需显式执行/确认。
- `keep=0` 的契约语义为禁用自动 prune，不等于删除全部备份；该语义已获用户批准（2026-09-30），当前实现与文档的差异核对及隔离验证由后续实现 PLAN 承接。
- 清理失败时逐项报告已删除/未删除，不能把部分成功报告为全成功。

## 5. 安全不变式

- 测试与生产仓库和备份数据隔离；任何备份操作不得跨环境查找同名仓库或备份。
- 恢复目标必须是显式选定的已注册仓库；绝不根据仓库名自动找另一个 root。
- backup restore/prune 遵循 `tags-and-policies.md` 的授权/确认边界，且必须逐次由本地人类操作者确认；pull 的无人值守（unattended）策略不适用于独立备份操作。
- 普通列举/查询不隐式触发创建、恢复或清理。
- 清理前预览与确认；恢复前保存可恢复状态；失败须报告部分副作用和恢复路径。
- 备份远端元数据、日志和错误中不得泄漏 PAT、token 或凭证。

## 6. 验收场景

| 编号 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| B1 | 创建并列举备份 | 对测试 root 中的仓库创建备份后列出 | 备份可识别且只出现在测试环境；生产备份集不变 |
| B2 | 恢复备份 | 选择一份有效备份并确认恢复 | 目标与影响先显示；当前仓库形成 pre-restore recovery copy；完成后结果可查 |
| B3 | 恢复失败 | 用损坏/不存在或不兼容的备份尝试恢复 | 显示失败原因；不静默覆盖原状态；恢复副本路径/可恢复状态可见 |
| B4 | 清理预览 | 为多个备份执行 prune preview | 仅列出将删除项；文件和元数据均未删除 |
| B5 | 清理执行 | 确认 preview 后执行 prune | 只删除确认列表；逐项报告部分失败，不触碰其他仓库/环境 |
| B6 | 保留数量为零 | 将 keep 设为 0 并创建新备份 | 不触发自动删除；已有备份保持可列举 |
| B7 | 与逻辑归档区分 | 归档仓库但未创建备份 | 归档不新增 backup entry，也不计入备份数量 |

## 7. 非目标与待确认

- 不冻结目录快照/tar 压缩包的具体格式、压缩参数、存储路径或远端存储实现。
- 保留期限/保留数量可以配置；默认值与多策略冲突规则在用户批准 SPEC 前保持提案。
- pull 冲突备份的 rename/reclone 原子性归 `repository-lifecycle`；本 SPEC 拥有操作者主动备份和 restore/prune。
